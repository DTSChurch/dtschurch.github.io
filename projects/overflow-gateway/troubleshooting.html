Troubleshooting

Most issues come down to a campaign that isn’t mapped, a gift that hasn’t settled yet, or the rolling sync window. The run summary tells you almost everything you need — this page explains how to read it and how to handle the trickier cases like failed gifts and cleaning up historical data.

Start With the Run Summary

After any run, open the job’s Result message. The Skip Reason Breakdown groups everything that didn’t import, with human-readable examples — campaign and donor names and dollar amounts, not bare IDs. Nine times out of ten the answer to “why didn’t this gift show up?” is right there.

Common Issues

SymptomLikely cause & fix
/overflow page doesn’t load, or the gateway/job is missing Migrations didn’t run. Confirm the DLL is in RockWeb\Bin and restart Rock. See Installation.
Job fails immediately or reports it can’t reach Overflow Check the gateway’s API Key and Client ID, that it’s Active, and that Server URL is correct (production is https://server.overflow.co).
Gifts skipped — “no campaign map / no account” The campaign isn’t mapped and there’s no fallback account. Add a Campaign Map, set a default Account on the gateway, or enable Create Accounts If Not Mapped.
A recent gift hasn’t appeared Stock and crypto only sync once they’re fully settled (liquidated / paid out). Failed or pending gifts are skipped by default. Re-run after it settles.
An older gift never imported It’s outside the Sync Days Back window (default 30). Temporarily widen the window, run once, then set it back — see Historical cleanup below.
A duplicate transaction Shouldn’t happen — gifts are keyed by their Overflow ID. If you see one, check whether it was also entered manually in Rock.
Batch total looks off after a cleanup You likely zeroed or deleted a gift in a closed batch. Use the reversal mode instead — see Failed Transaction Handling and the closed-batch caution below.

Failed Transaction Handling

The Failed Transaction Handling job setting controls what happens to non-settled and failed / cancelled gifts. (Refunds, voids, and chargebacks always create a linked reversal regardless of this setting.)

ModeBehaviorWhen to use
1 — Only import settled Default Skips failed / pending / processing / abandoned / cancelled gifts entirely until they settle. The safe default for most churches — only real, settled money lands in Rock.
2 — Import all, zero out Imports everything; sets failed / cancelled gifts to $0.00 with an explanatory note. When you want a record that the attempt happened, with no dollar impact.
3 — Import all, reverse Imports everything; creates an offsetting reversal for failed / cancelled gifts so they wash to zero. When the target gifts may sit in closed batches — this is the only safe cleanup mode for those (see below).
4 — Import all, delete Imports everything; deletes failed / cancelled gifts (reported as Transactions Removed). When you want them gone entirely and they’re only in open batches.

Closed-batch caution. Modes 2 (zero) and 4 (delete) mutate the original transaction, which throws off the total of a batch that’s already closed / reconciled — batching only recalculates totals for open batches. If the records you’re cleaning up are in closed batches, use mode 3 (reverse) instead: the original stays put and the offsetting entry posts to a new open batch as an adjustment. Reserve modes 2 and 4 for records still in open batches.

Cleaning Up Historical Data

The job pulls a rolling Sync Days Back window (filtered on when a gift was last updated in Overflow). Settings like Create Accounts If Not Mapped and the failed-handling modes only affect the records the job re-fetches in that window. To clean up data older than the window:

  1. Temporarily widen Sync Days Back to cover the date range you need to fix.
  2. Run the job once (Run Now).
  3. Set Sync Days Back back to its normal value (e.g. 30).

Because the sync is idempotent, this re-processes the older gifts without duplicating the ones already imported.

Getting Support

If a problem isn’t explained by the run summary, gather the job’s Result message and any related entries in Admin Tools → System Settings → Exception List, then reach out to DTS with those details. Note your Rock version and the plugin version (see the Changelog).
