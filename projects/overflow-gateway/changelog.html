Version History

Release notes for the Overflow Gateway plugin. The format follows Keep a Changelog and the project uses semantic versioning.

v1.0.4 — 2026-06-19

Reversals, chargebacks & smarter mapping

Added

  • Chargeback handling. A chargeback now creates an offsetting reversal with the same date and amount as the original (so they net to zero), linked to the original so Rock’s UI shows it as a refund, with a “Chargeback on <date>” note.
  • Linked reversals for refunds & voids. Refunds and voids are now linked to the original transaction so Rock displays them as refunds (previously they were standalone entries).
  • “Failed Transaction Handling” job setting with four modes — only import settled (default), import and zero out, import and reverse, or import and delete. See Troubleshooting.
  • “Create Accounts If Not Mapped” job setting (default off): an unmapped campaign / subcampaign auto-creates a Rock account and its map, then the gift is assigned to it. Idempotent across runs.
  • New summary counts — Accounts Created (subscriptions & transactions) and Transactions Removed (delete mode).

Changed

  • Reversal logic consolidated into a single idempotent path shared by one-time and recurring gifts.
  • Human-readable skip reasons. The breakdown now shows campaign / subcampaign and donor names with dollar amounts instead of bare IDs.

v1.0.3 — 2026-01-08

Stock & crypto currency types

Added

  • Stock & crypto currency types. New gateway settings let you choose the Rock currency type recorded for stock and crypto gifts, with refined contribution-sync handling for those gift types.

Changed

  • Refund refinements. Refunded gifts post as offsetting negative transactions using a {id}-R code, and VOIDED gifts are now treated as refunds.
  • Refund initiation accepts both success responses from Overflow and returns the refund ID.
  • More resilient gateway connection — the Server URL and other settings are read reliably, with the API connection handling tightened up.

v1.0.2 — 2025-12-03

Refunds & programmatic credit

Added

  • Refund handling. Refunded contributions are detected and posted as negative-amount transactions, keeping a clean giving history. New settled statuses recognized (CONFIRMED, PAID_OUT, REFUNDED), with summaries prefixed “REFUND:” for easy identification.
  • Programmatic refund initiation. The gateway can initiate a refund through the Overflow API (subject to Overflow’s $1,000 limit), with clear error messages on failure.
  • Enhanced logging for unknown statuses and contribution types during sync.

Changed

  • Improved error handling and logging in the sync job for easier debugging.

v1.0.1 — 2024-11-04

Naming & packaging

Added

  • Plugin lock file for consistent builds.

Changed

  • Renamed the project to com.overflow.Gateway for consistent naming, updating namespaces and block paths.
  • Improved API-client and sync-job error handling.

Fixed

  • Admin-block registration and component path corrections.

v1.0.0 — 2024-10-15

Initial release

  • Gateway component — full Overflow API integration, including cryptocurrency and stock donations, saved payment methods, and scheduled-payment cancellation.
  • Sync job — donor sync with person matching, campaign-to-account mapping, subscription (recurring giving) sync, contribution sync, and configurable batch grouping (date / campus / payment method).
  • Entity models — Person Map (Overflow donor ↔ Rock person) and Campaign Map (Overflow campaign ↔ Rock account).
  • Admin UI — Person Map and Campaign Map list + detail blocks.
  • Migrations — database setup for the mapping tables, gateway, pages, and job.
